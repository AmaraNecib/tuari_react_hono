# M1.1 — API Design Document

## Rust Core Scaffolding and Shared Crypto Module

**Issue:** #71
**Target Version:** 0.1.0
**Module Architecture:** `.scratch/implementation/m1.1-module-design.md`

---

## Scope

This issue creates the foundational infrastructure that all downstream Rust Core modules depend on:

1. `crypto.rs` — Shared cryptographic utilities
2. `error.rs` — Standard `RustCoreError` type
3. Module scaffolding in `lib.rs`
4. `Cargo.toml` dependency additions

**Out of scope:** LicenseManager, ClockTracker, Recovery — these are separate issues.

---

## Public API

### `crypto.rs`

```rust
/// Error type for cryptographic operations.
#[derive(Debug)]
pub enum CryptoError {
    InvalidSignature,
    InvalidKey,
    InvalidInput,
    CryptoBackend(String),
}

/// Verify an Ed25519 signature against a public key.
///
/// # Arguments
/// * `public_key` - 32-byte Ed25519 public key
/// * `message` - The message that was signed
/// * `signature` - 64-byte Ed25519 signature
///
/// # Returns
/// * `Ok(())` if the signature is valid
/// * `Err(CryptoError::InvalidSignature)` if the signature is invalid
/// * `Err(CryptoError::InvalidKey)` if the public key is malformed
pub fn ed25519_verify(
    public_key: &[u8; 32],
    message: &[u8],
    signature: &[u8; 64],
) -> Result<(), CryptoError>;

/// Compute the SHA-256 digest of data.
pub fn sha256_digest(data: &[u8]) -> [u8; 32];

/// Generate cryptographically secure random bytes.
///
/// Wraps `OsRng`. Panics only if the OS entropy source fails.
pub fn generate_random_bytes(len: usize) -> Vec<u8>;
```

### `error.rs`

```rust
/// Standard error type for all Rust Core operations.
///
/// Every Rust Core module returns `Result<T, RustCoreError>`.
/// This enables callers (Tauri Adapter) to handle all errors uniformly.
#[derive(Debug)]
pub enum RustCoreError {
    // --- Crypto errors ---
    InvalidSignature,
    CryptoError(String),

    // --- License errors ---
    LicenseFileNotFound,
    Expired,
    InvalidFormat,
    InvalidPayload,
    ActivationFailed(String),

    // --- Clock errors ---
    ClockTampered { estimated_time: DateTime<Utc>, reason: String },

    // --- File system errors ---
    IoError(String),
    InsufficientDiskSpace { required: u64, available: u64 },

    // --- Internal errors ---
    Internal(String),
}

impl std::fmt::Display for RustCoreError { ... }
impl std::error::Error for RustCoreError { ... }
impl From<std::io::Error> for RustCoreError { ... }
```

## Internal Dependencies

```
crypto.rs  →  no dependencies (uses ed25519-dalek, sha2 crates)
error.rs   →  no dependencies (uses std)
```

Neither module depends on the other, and neither depends on any other Rust Core module. This allows them to be developed and tested independently.

## Implementation Risks

| Risk | Mitigation |
|------|------------|
| `ed25519-dalek` v2 API differs from v1 | Pin version explicitly, verify tests pass |
| `base64` crate version may have breaking changes | Pin `base64 = "0.22"`, test url-safe encoding/decoding |
| Windows `OsRng` behavior | No action needed — `OsRng` is cross-platform and well-tested |
| `tauri::` accidentally imported in core modules | Add a CI check (`grep -r "tauri::" src/*.rs --include="*.rs" \| grep -v lib.rs`) |
| Long compile times for new deps | Added `Swatinem/rust-cache` to CI in M0.1 |

---

## Test Implementation Strategy

Per TDD (Red → Green → Refactor):

1. **Write tests first** — all tests above written as `#[test]` functions
2. **Implement** — write minimal code to pass tests
3. **Refactor** — clean up, ensure no Tauri imports
4. **Verify** — `cargo test` passes, `cargo check` on CI
