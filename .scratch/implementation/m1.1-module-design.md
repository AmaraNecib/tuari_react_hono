# M1.1 — Module Architecture Design

## Project Module Boundaries

This document defines the high-level module boundaries for the entire Rust codebase. It is the permanent reference for where code belongs and how modules communicate.

---

## Module Inventory

### Rust Core (Platform Library)

These modules form the Trust Authority. They must contain **no Tauri imports** and must be testable with `cargo test` alone.

| Module | File | Responsibility | Cannot Depend On |
|--------|------|---------------|------------------|
| **Crypto** | `crypto.rs` | Ed25519 verification, SHA-256 hashing, secure random generation | Any other Rust Core module |
| **Error** | `error.rs` | `RustCoreError` enum, standard error types for all Rust Core operations | Any other Rust Core module |
| **License** | `license.rs` | `LicenseManager` struct, license file I/O, signature verification, grace period, key rotation, feature evaluation | Tauri, Hono, Desktop |
| **Clock** | `clock.rs` | Clock tracker, monotonic tamper detection, `ClockStatus` enum | Tauri |
| **Update** | `update.rs` (future, M2) | Update package verification, manifest parsing | Tauri |
| **Recovery** | `recovery.rs` | File backup/restore, atomic rename, disk space check | Tauri |

### Tauri Adapter

These modules bridge the Rust Core to the desktop environment. They import `tauri::` types.

| Module | File | Responsibility | Cannot Depend On |
|--------|------|---------------|------------------|
| **Commands** | `lib.rs` | `#[tauri::command]` handlers, IPC routing | — |
| **Sidecar** | `lib.rs` | Process lifecycle, env var provisioning | — |

### Boundary Rule

```
Rust Core modules → call each other via plain function calls
Tauri Adapter → calls Rust Core modules
Rust Core modules → MUST NOT import tauri::
```

## Dependency Graph (Rust Core)

```
crypto.rs
    ↑
error.rs
    ↑
license.rs  ←── clock.rs
    ↑
recovery.rs
    ↑
update.rs (future, M2)
```

- `crypto.rs` and `error.rs` have zero dependencies on other Rust Core modules.
- `license.rs` depends on `crypto.rs` (signature verification) and `error.rs` (error types).
- `clock.rs` depends on `error.rs` only.
- `recovery.rs` depends on `error.rs` only.
- `update.rs` (future) depends on `crypto.rs` and `error.rs`.
- No circular dependencies exist.

## Internal Folder Layout

Since all Rust Core modules live in the same crate (`apps/desktop/src-tauri/src/`), there is no deep folder hierarchy. Each module is a single `.rs` file with a clear public API.

```
apps/desktop/src-tauri/src/
├── main.rs              # Entrypoint (Tauri)
├── lib.rs               # Tauri Adapter: commands, setup, IPC
├── crypto.rs            # Rust Core: shared crypto utilities
├── error.rs             # Rust Core: standard error type
├── license.rs           # Rust Core: LicenseManager
├── clock.rs             # Rust Core: ClockTracker
├── recovery.rs          # Rust Core: file backup/restore
├── update.rs            # Rust Core (future): update verification
└── tests/               # Integration tests
    └── m1_integration.rs
```

**Justification:** A flat file structure within a single crate is appropriate for <20 source files. Modules communicate via `pub` functions and structs. If the crate grows beyond ~20 source files, consider splitting into subdirectories by module (`crypto/`, `license/`, `clock/`).

## Public Surface

Every module exposes a minimal public API. Everything else is `pub(crate)` or private.

| Module | Public Types/Functions |
|--------|----------------------|
| `crypto.rs` | `ed25519_verify()`, `sha256_digest()`, `generate_random_bytes()`, `CryptoError` |
| `error.rs` | `RustCoreError` enum |
| `license.rs` | `LicenseManager`, `LicenseInfo`, `LicenseStatus`, `LicensedFeature`, `Edition` |
| `clock.rs` | `ClockTracker`, `ClockStatus`, `check_clock_consistency()`, `grace_remaining()` |
| `recovery.rs` | `backup_directory()`, `restore_directory()`, `backup_file()`, `restore_file()`, `atomic_rename()`, `disk_space_available()` |

## Coupling Review

| Risk | Status |
|------|--------|
| Cyclic dependencies | ✅ None. All dependencies flow from specific → general (license → crypto). |
| Module knows too much | ✅ Each module owns one concern. LicenseManager doesn't know about filesystem backup format. |
| Leaky internals | ✅ Public API is explicit. Non-public items use `pub(crate)` or no visibility modifier. |
| Duplicate crypto code | ✅ `crypto.rs` is the single source of truth for Ed25519 and SHA-256. License and Update both call into it. |
| Tauri coupling in core | ✅ Enforced by code review: no `tauri::` import in core modules. |
