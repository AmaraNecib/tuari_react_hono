# M1.5 — Key Rotation and Trust Chain

## Public API

### Structs

```rust
// apps/desktop/src-tauri/src/license.rs

/// A key rotation certificate that authorizes a new signing key.
pub struct RotationCertificate {
    /// The new Ed25519 public key (32 bytes)
    pub new_public_key: [u8; 32],
    /// When this key becomes effective
    pub effective_from: DateTime<Utc>,
    /// SHA-256 of the previous public key
    pub previous_key_id: String,
    /// Reason for rotation (scheduled, emergency, compromise)
    pub rotation_reason: String,
    /// Root CA signature over the certificate fields
    pub root_ca_signature: [u8; 64],
}
```

### Changes to LicenseManager

- `EMBEDDED_ROOT_CA_KEY` — public key of the Root CA (embedded at build time)
- `with_keys()` — unchanged
- `initialize()` — also loads rotation certificates via `load_rotation_certificates()`
- `load_rotation_certificates(data_dir)` — scans for `key-rotation-*.json`, validates Root CA sig
- `verify_signature(payload, signature)` — tries all trusted keys (existing + rotation certs)

## Internal Dependencies

```
license.rs → uses: crypto.rs (ed25519_verify, sha256_digest), error.rs (RustCoreError)
```

## Planned Tests

- Rotation certificate parse and verify
- Root CA signs a valid rotation cert — key is added to trusted list
- Invalid Root CA signature on rotation cert — rejected
- Expired/not-yet-effective rotation cert — rejected
- Multiple rotation certs loaded — all keys trusted
- initialize() loads rotation certs from data dir
- License signed with rotated key still verifies

## Implementation Risks

- Root CA key embedding is similar to EMBEDDED_PUBLIC_KEY — just a new constant
- The RotationCertificate must be signed by Root CA, verified using Root CA's public key
- SHA-256 of old key is used as key_id for chain verification

## Deviations from Architecture

- Simplified: no separate key-rotation.json file format yet; rotation certs are
  loaded from `<data_dir>/key-rotation-*.json` files
- Root CA verification reuses the same ed25519_verify function from crypto.rs
