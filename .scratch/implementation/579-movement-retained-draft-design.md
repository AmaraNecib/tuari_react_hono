# Retain movement drafts across failed refreshes

Base: `c312d7b84b84df1cfb2fef129ff087ef11648b6b`. Verification mode: focused-local / CI-final-pending. Tier: high assurance; the reachable failure can discard an inventory operation and confuse retained stock with authoritative current stock.

The page owns movement-dialog visibility; the form owns the in-progress draft. Readiness for the first mount remains successful stock and definitions. Once mounted, cached query `data` is independent of `isError`: a background failure leaves both datasets available and the same form instance mounted. Show a retryable error and disable submission while either dependency is errored; keep fields editable so the draft remains intact. A successful refetch supplies authoritative data and existing form reconciliation continues to handle stock/definition changes and asset-override identity. Do not change default-charge lookup handling. Submission is blocked in both the button and the form handler, including while the failed query retries. Fields stay editable. The read-error message and retry button live inside the dialog, not in the modal-hidden page behind it.

Module/seam: the existing page-to-form interface passes inventory contents and definitions. No seam moved. Vocabulary: readiness means both queries have successful initial results; retained data means a prior result remains after a failed refetch. Applied wisdom: dashboard stat retained-data lesson; it distinguishes stale retained values from first-load errors. Also applied: dialogs snapshot identity, not derived data. Deleting the movement module would spread draft construction, exact-price validation and eligibility reconciliation into callers; it still earns its existing interface. Only the existing page-to-form seam gains a submission-block flag and rendered retry feedback.

## Diagnosis and discrimination

The production keys are `[...exactCommercePrefix(financialClient.inventory), "operator", "location", { warehouseId: "same" }]` and the same bound-client/owner prefix plus `"definitions"`. The prefix includes a WeakMap client-identity scope. Tests now verify each original query settled successfully with idle fetch state, target its exact key, verify an active observer, and assert the failed transport caused the real query to enter error while retaining its data. There is no mocked hook or synthetic QueryClient error. The prior key-mismatch suspicion was not established; the concrete UI defect in the recovered draft was alert placement outside the dialog, hidden by modal accessibility isolation. Moving the feedback inside the dialog fixes the inaccessible retry without weakening role assertions.

Four retained-draft cases cover both read failures crossed with sale and transfer. They pin the same dialog/form DOM identity, operation, selected entry, quantity 2, typed project destination, exact four-place unit price 12.3456 and note. They verify no RPC write after both a disabled-button click and forced form submit, keep submission blocked during a deferred retry, and assert independent literal outbound/transfer payloads only after recovery. Destination persists even through sale mode. Initial arrival-order and uncached failure/empty/retry tests remain. Asset replacement tests now cover both zero and custom 23.47 overrides across same-asset refresh and replacement, inactive definitions, exhausted stock and explicit choice.

Focused replay with the actual base page/form and the new harness fails all four retained-draft cases because the dialog disappears after refetch failure. A separate handler-only mutant, removing the block check while retaining the disabled button, fails all four with one forbidden write. Both probes restore exact source bytes in finally blocks. The first expanded sale fixture used an invalid six-place price and remained blocked after recovery; correcting the fixture to the contract's four-place price made it valid, without changing validation.
