# M1.2 — License Types and Schemas

Public API design for the shared Zod schema definitions.

## Public API

### Enums

```typescript
// packages/contracts/src/license.ts

const licenseIdSchema: z.ZodString         // pattern: LCE-YYYYMMDD-[A-Z0-9]{6}
const editionSchema: z.ZodEnum<[standard, professional, enterprise]>
const licenseTypeSchema: z.ZodEnum<[perpetual, subscription, trial, grace]>
const licensedFeatureSchema: z.ZodEnum<[lan_server, multi_user, encrypted_db, ...]>
```

### Objects

```typescript
const licenseMetadataSchema: z.ZodObject    // version, buildNumber — extensible
const licensePayloadSchema: z.ZodObject     // full payload (all fields from Section 2.2)
```

### Exported types (inferred)

```typescript
type Edition = z.infer<typeof editionSchema>
type LicenseType = z.infer<typeof licenseTypeSchema>
type LicensedFeature = z.infer<typeof licensedFeatureSchema>
type LicensePayload = z.infer<typeof licensePayloadSchema>
```

## Internal Dependencies

```
license.ts  →  depends on: none (self-contained Zod schemas)
index.ts    →  exports: license.ts
```

No dependency on any other Contracts module.

## Planned Tests

- licenseId validates correct format (`LCE-20260701-ABC123`) and rejects bad
- edition accepts all three values, rejects invalid
- licenseType accepts all four values, rejects invalid
- licensedFeature accepts all valid feature names
- licensePayload validates a complete payload
- licensePayload rejects missing required fields
- licensePayload rejects invalid edition
- licensePayload rejects future `validFrom` after `validUntil`
- metadata is optional and extensible

## Implementation Risks

- The Rust `LicensedFeature` enum has different casing (PascalCase in Rust vs
  snake_case in JSON). The Zod schema should match the JSON wire format
  (snake_case), and the Rust side will deserialize accordingly.
- `validUntil` is optional — Zod `.optional()` for perpetual licenses.

## Deviations from Architecture

None — the design follows Section 2.2 of the Licensing Architecture exactly.
