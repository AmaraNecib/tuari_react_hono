# M6.1 Extension — Trust Infrastructure & Key Rotation

## Problem

M6.1 implemented update signing with a single hardcoded `UPDATE_PUBLIC_KEY`.
`license.rs` already has key rotation via `RotationCertificate` + `ROOT_CA_PUBLIC_KEY`,
but it's not shared with `update.rs`.

## Solution

Extract shared rotation logic into a new `trust/` module and wire both systems to use it.

## New Module: `apps/desktop/src-tauri/src/trust/`

```
trust/
├── mod.rs          ← public interface, re-exports
├── root_ca.rs      ← ROOT_CA_PUBLIC_KEY constant (moved from license.rs)
├── rotation.rs     ← RotationCertificate, KeyPurpose, verify()
└── trust_store.rs  ← load_trusted_keys()
```

### `trust/mod.rs`

Re-exports key types:
- `pub use root_ca::ROOT_CA_PUBLIC_KEY;`
- `pub use rotation::{RotationCertificate, KeyPurpose};`
- `pub use trust_store::load_trusted_keys;`

### `trust/root_ca.rs`

```rust
pub(crate) const ROOT_CA_PUBLIC_KEY: [u8; 32] = [0x00; 32];  // placeholder
```

### `trust/rotation.rs`

```rust
#[derive(Debug, Clone, PartialEq, Eq)]
pub enum KeyPurpose {
    License,
    Update,
}

// RotationCertificate with added purpose field
pub struct RotationCertificate {
    pub cert_type: String,
    pub new_public_key: String,
    pub effective_from: String,
    pub previous_key_id: String,
    pub rotation_reason: String,
    pub purpose: KeyPurpose,  // NEW field
    pub root_ca_signature: String,
}

impl RotationCertificate {
    pub fn verify(&self) -> Result<[u8; 32], RustCoreError>;
    pub fn verify_with_key(&self, root_ca_key: &[u8; 32]) -> Result<[u8; 32], RustCoreError>;
}
```

### `trust/trust_store.rs`

```rust
pub fn load_trusted_keys(data_dir: &Path, purpose: KeyPurpose) -> Result<Vec<[u8; 32]>, RustCoreError>;
```

Scans `key-rotation-*.json` in `data_dir`, verifies each cert's Root CA signature,
filters by `purpose` field, and returns the trusted public keys.
