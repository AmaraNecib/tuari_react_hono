# M1.4 — Clock Tracker and Grace Period

## Public API

### Structs

```rust
// apps/desktop/src-tauri/src/clock.rs

pub struct ClockTracker {
    last_seen_wall: i64,      // Unix timestamp of last wall clock read
    last_monotonic: Instant,  // Monotonic time at last write
    install_wall: i64,        // Wall clock at first-ever install
}

pub enum ClockStatus {
    Trusted,
    Suspicious { estimated_time: DateTime<Utc>, reason: String },
}
```

### Functions

```rust
pub fn check_clock_consistency(state_dir: &Path) -> Result<ClockStatus, RustCoreError>;
pub fn grace_days_remaining(state_dir: &Path) -> Option<i64>;
pub fn is_within_grace_period(state_dir: &Path) -> bool;
```

### Changes to LicenseManager

- `initialize()` calls `check_clock_consistency()` and uses estimated time
- `status()` considers grace period when no license is active
- `days_remaining()` considers grace period

## Implementation Plan

1. Replace the `ClockStatus` stub in `clock.rs` with real logic
2. Implement `check_clock_consistency()` — compare wall vs monotonic
3. Implement grace period helpers
4. Wire `ClockTracker` into `LicenseManager`
5. Tests: clock rollback, clock fast-forward, monotonic mismatch, grace period edge cases

## Deviations from Architecture

- Grace period is simplified to a basic days-remaining check
- Three-phase expiry (Active/Warning/ExpiredGrace/Locked) is partially in
  LicenseManager::status() — the read-only enforcement is a UI concern
