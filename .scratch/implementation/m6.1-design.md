# M6.1 — sign-update CLI Tool

## Public API

### `scripts/sign-update.mjs`

```bash
node scripts/sign-update.mjs --private-key <path> --manifest <path> --output <path>
```

- `--private-key` (required): Path to Ed25519 private key PEM file
- `--manifest` (required): Path to `manifest.json` to sign
- `--output` (required): Output file path for signed manifest
- `--help`: Show usage

Output format: `<base64url(canonical_json)>.<base64url(signature)>`

### `scripts/verify-signed-manifest.mjs`

```bash
node scripts/verify-signed-manifest.mjs --public-key <path> --manifest <path>
```

- `--public-key` (required): Path to Ed25519 public key PEM file
- `--manifest` (required): Path to signed manifest file
- `--help`: Show usage

Exits 0 if valid, non-zero if invalid.

### `scripts/generate-dev-update-keys.mjs`

```bash
node scripts/generate-dev-update-keys.mjs
```

- Outputs public key as Rust byte array: `pub const UPDATE_PUBLIC_KEY: [u8; 32] = [...]`
- Outputs private key PEM file for local signing
- `--output-dir <path>`: Output directory (default: current directory)

## Internal Dependencies

All scripts use only Node.js built-in modules:
- `node:crypto` for Ed25519 signing/verification, key generation
- `node:fs/promises` for file I/O
- `node:path` for path resolution

## Canonical JSON Serialization

Deterministic field order: sort keys alphabetically, no whitespace.
Must match the Rust `serde_json` default serialization for the `UpdateManifest` struct:
- `version`
- `platform`
- `minSupportedVersion`
- `checksum`
- `files` (array of objects with sorted keys: `hash`, `path`, `size`)

## Implementation Risks

- Ed25519 key format compatibility between Node.js `crypto.generateKeyPairSync('ed25519')` (PKCS#8 private, SPKI public) and what Rust expects (raw 32-byte seed/secret key).
- Canonical JSON must produce byte-identical output to what Rust's `serde_json` produces when serializing `UpdateManifest`.

## Matching `update.rs` Verification

The `verify_package_signature()` function in `update.rs` calls `crypto::ed25519_verify(public_key, manifest_bytes, signature_bytes)`.

This means:
- `manifest_bytes` = the canonical JSON bytes (NOT base64url encoded)
- `signature_bytes` = the raw 64-byte Ed25519 signature

The signed manifest format `<base64url(canonical_json)>.<base64url(signature)>` is designed so that:
1. Split on `.` to get `canonical_json_part` and `signature_part`
2. Base64url-decode both
3. Verify `ed25519_verify(public_key, canonical_json_bytes, signature_bytes)`
