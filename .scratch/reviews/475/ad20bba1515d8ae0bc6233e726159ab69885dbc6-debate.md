## Critic findings

### T1 — The new finance test pins the chain, not the per-account fold it names
Severity 2 (Minor). Location: finance.service-coverage.test.ts:1066-1098; source finance.service.ts:1024-1036.
The per-account SETTLEMENT fold runs when account.status === "SETTLED" and folds
Math.abs(entry.signedAmountDzd) through accumulateDebtReportMoney; totalSettledDzd then folds
accountSettled through the same guard. With one SETTLED account the two folds receive the same
MAX+1, so if the per-account guard were removed the totalSettledDzd guard would still throw and the
test would still pass — it does not uniquely pin the per-account accumulator.
Defender: the comment's "refuses here instead of at totalSettledDzd" is about runtime first-fire and
is literally true (the reduce throws before the totalSettledDzd line). It is a valid red→green
regression test: pre-fix (d6164c65) no report guard existed, so the assertion would fail.
Chain-level coverage is the granularity the prior round's tests already use (ea637d2f N1).
Verdict: not a flaw; wording/coverage-granularity note only.

### T2 — The new consumable test likewise pins the chain, not the accumulator it names
Severity 2 (Minor). Location: inventory-report-money-bound.test.ts:158-171; source inventory.service.ts summary folds + totalValueDzd cross-sum.
The consumable accumulator is first to fire at runtime, but totalValueDzd is fed rawAssets(0) +
rawConsumables(MAX+1) and would also throw if the consumable fold were unguarded. Non-vacuous
(fails pre-fix), and it is a distinct accumulator from the ASSET fold covered by the first test.
Verdict: accept, note only.
