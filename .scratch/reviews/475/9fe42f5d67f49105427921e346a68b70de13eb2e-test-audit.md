## 3. Non-vacuity re-confirmation of the two new tests (delta did not touch them)

**AC16 (fractional).** Pre-fix guard read from `git show a8058778:apps/api/src/modules/company/report.helpers.ts`:
`if (!Number.isFinite(nextDzd) || nextDzd > MAX_MONEY_DZD) onOverflow()`. HEAD uses
`amountDzd > MAX_MONEY_DZD - currentDzd`. Node check on this machine with
`MAX = Number.MAX_SAFE_INTEGER = 9007199254740991`:

```
M+0.25===M      → true
(M+0.25)>M      → false
0.25 > M-M      → true
ULP at M        → 1
```

So the old guard emits the summary (`totalValueDzd = MAX`) → `captureError` returns `null` →
`expectBusinessRule(null)` fails. The headroom guard throws `InventoryError`/`BUSINESS_RULE`. The test
is therefore discriminating and red pre-fix — **unchanged from round 4**, since the test file and the
guard are both identical between `f76d6c9b` and `9fe42f5d`.

**AC17 (rethrow).** Pre-fix `git show a8058778:apps/api/src/rpc/handlers/reports.ts` has
`function toReportOrpcError(...)` **not exported** and `return error` for the non-`appError` branch.
Red pre-fix holds on both counts: the test's `import { toReportOrpcError }` cannot resolve a
non-exported binding (module-load failure ⇒ red), and even if it resolved, `toThrow(boom)` fails
because the old body returned `boom`. (Round-4 precision note: the red was guaranteed by the missing
export as well as by the return→throw change — the assertion still targets the behavior change.)
The positive branch (`appError` → `ORPCError` code `BUSINESS_RULE`) is asserted in the same test.

Red re-execution against pre-fix source was **not** re-run this round: it requires checking out the
