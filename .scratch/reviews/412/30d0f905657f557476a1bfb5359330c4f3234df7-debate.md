## Dismissed with evidence

- **Assignment `endDate` convention / `""` open-ended.** `assignEmployeeWorkplace`
  (`sqlite-company.repository.ts`) closes the old project assignment with the
  reassignment instant (`endDate: ts`), so the half-open `[start, end)` model is
  correct for the real writer. `employeeProjectAssignmentSchema.endDate` is
  `timestampSchema.nullable()` and `timestampSchema` is
  `z.string().datetime({ offset: true })`, which rejects `""`; no producer emits
  it. The contract's `algeriaDay`-based tests pin the handoff.
- **`expectedAmountDzd` meaning change / aggregate mixing.** Issue #412 asks for
  the prorated proposal and the design record (`412-design.md`) records the
  meaning change and the legacy-row policy. Changing persisted semantics would
  need a data migration, which is out of this PR's subject.
- **`createSalaryPayment` re-read with `!`.** The read-back is the pre-existing
  shape (`listSalaryPayments(...).find(...)!`); the `days` column and the split
  table are created unconditionally by `schemaStatements` (`CREATE TABLE IF NOT
  EXISTS`) plus the additive `ALTER`, and `ensureDatabaseSchema` only swallows
  duplicate-column errors. A SELECT would fail before the mapper saw a missing
  column.
- **WEEKLY `days = 30` / wire `days` default 30 for DAILY.** Issue #412 lists
  weekly salaries as out of scope and keeps the enum for legacy rows only.
  Every production caller (dialog and quick form) sends `days` explicitly; no
  create path relies on the default.
- **Earlier project's open window swallowing a later project.** The schema has
  `UNIQUE ... employee_project_assignment (employee_id) WHERE status = 'ACTIVE'`
  (one active assignment per employee) and `assignEmployeeWorkplace` closes the
  outgoing assignment when it reassigns, so two non-archived overlapping windows
  for one employee cannot exist in real data. `home-view` also drops ARCHIVED
  rows. The derivation's project-id tie-break is defense in depth.
- **Zone-less timestamps.** `timestampSchema` requires an offset and the writers
  emit `Z`/`+01:00`, so the zone-less `new Date("...T00:00:00")` case is not
  reachable through the stack.

## Reported, deferred (low, out of the fix scope)

- `employee_salary_payment_split` has no `UNIQUE(payment_id, project_id)`; the
  service is the only writer and rejects duplicates. Adding it to the raw DDL
  only would drift from the Drizzle table and would not apply to an existing
  table (`CREATE TABLE IF NOT EXISTS`), so it is left as a follow-up.
- `company.repository-mappers.ts#mapEmployeeSalaryPayment` hardcodes
  `projectSplits: []` but has no production caller (the live read path is
  `toSalaryPayment(r, splitsByPayment.get(row.id) ?? [])`).
- Raw SQL has `CHECK ("days" > 0)`; the Drizzle table omits it. Divergence noted.
- Web layer re-declares `SalaryProjectAssignmentWindow`/`SalaryPeriodType` from
  `@tuari/contracts`, and the literal `30` appears at the DB/contract/web layers.
