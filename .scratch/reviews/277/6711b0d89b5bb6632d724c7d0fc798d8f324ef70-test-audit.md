## Edge Case Hunter

| # | Risk | Finding | Decision |
|---|------|---------|----------|
| T1 | 🟡 | **Overpaid (negative) balances not pinned in the canonical contracts suite.** The flip inverts meaning for negatives (overpaid PAYABLE `-300` → net `+300` = "they owe us"), and that state is an explicit domain case (web meta tests comment "We overpaid: the supplier now owes us"). `debt-helpers.test.ts` pins only positive/zero balances; negatives are covered only transitively (web `debt-utils.test.ts` 5 meta cases and API `getDebtAccountBalanceLabel({currentBalance:-5,direction:"PAYABLE"})` → "لنا عنده", both routed through the shared helper). | **RECOMMENDED FIX (cheap, non-blocking).** Add two pins to `debt-helpers.test.ts`: `getDebtAccountNetContribution({currentBalance:-300,direction:"PAYABLE"})` → 300 and `getNetDebtBalance([{currentBalance:-300,direction:"PAYABLE"}])` → 300. Today the behavior is correct and transitively tested; the canonical lock should be self-contained. |
| T2 | 🟡 | **`NaN`/`±Infinity` input propagates silently** — `signed === 0 ? 0 : signed` passes `NaN` through; reduce sums to `NaN`. | **DISMISSED.** Pre-existing property of both originals; inputs are wire-gated by `z.number()` schemas; out of scope for a move-refactor. No regression. |
| T3 | 🟢 | `-0` edge: `{currentBalance: 0, direction: "PAYABLE"}` → old code returned `-0`, which fails `toBe(0)` under `Object.is`. New code normalizes to `0` and the test passes. | **VERIFIED.** The "zero is zero regardless of direction" test (`debt-helpers.test.ts:22-24`) is only meaningful because of the normalization — this is a genuine edge-case catch, not dead coverage. |
| T4 | 🟢 | `getNetDebtBalance` over mixed lists with zero-balance accounts, large magnitudes, non-integers — plain IEEE-754 addition, no rounding/overflow handling anywhere in the originals. | **DISMISSED.** Same semantics as both originals (pure sum); DZD amounts are integers at the wire. |
