## Residual risks (documented)

- **R1**: No automated tripwire against re-introduction of a second sign-flip
  copy; contracts test is the sole runtime line of defense. Mitigation:
  single-source is the issue's explicit design; any future debt-sign change
  must touch `debt-helpers.ts` and be reviewed there.
- **R2**: Negative (overpaid) balances are not explicitly pinned in the
  canonical contracts suite (covered transitively via web meta + API label
  tests) — see test-audit T1.
- **R3**: `NaN`/`Infinity` balances would pass the `-0` guard unchanged
  (pre-existing property of the originals; inputs are wire-gated by
  `z.number()` schemas; out of scope).
- **R4**: `-0` normalization means the contracts implementation is not
  byte-identical to the originals in the zero case — provably benign at all
  current call sites (C1).
