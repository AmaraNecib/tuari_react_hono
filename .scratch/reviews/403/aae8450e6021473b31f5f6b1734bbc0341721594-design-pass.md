## domain-modeling

The change names one concept once: this installation's API sidecar identity is
the absolute `<install>/bin/api-runtime/dist/index.cjs`. `api_runtime_dir` and
`api_sidecar_entry_path` are the single source for that layout, shared by spawn,
the portable-layout probe, and stale cleanup. No new vocabulary was invented;
`api-runtime` / `index.cjs` stay layout constants, no longer a kill rule.

## codebase-design (deletion test)

- `is_api_sidecar_command_line` is a pure predicate with a real seam (command
  line + this install's dir) — testable without process I/O.
- `command_line_contains_path` earns its place: deleting it reintroduces
  substring over-kill (`.map`, `--entry="..."`).
- `api_runtime_dir` and the boundary helpers are thin, but each removes a real
  duplication (layout string, before/after boundary logic); not speculative.
- The unreachable `expected.is_empty()` branch was deleted rather than tested.

## improve-codebase-architecture

Friction removed: the layout string is now stated once, so a future runtime
layout move changes one place. Friction created: the predicate depends on the
process command line spelling matching `resource_dir()`; Windows 8.3/symlink
spelling divergence is a fail-safe false negative, filed as an out-of-scope
note. No sprawl; the change stayed inside the desktop crate plus a doc line.

## Outcome

Nothing found that blocks merge. The one accepted trade-off (a sidecar orphaned
by an in-place install relocation is no longer reclaimed) is documented in
