## Dispositions

- **C1**: `command_line_contains_path` accepts a path preceded by whitespace.
  Rejecting space-separated values would create a false negative for
  `node --inspect <path>`, which is a legitimate way to run the sidecar. The
  predicate only runs over node processes and the argument is this install's
  absolute sidecar path; distinguishing a launcher from a reference needs full
  argv inspection. #403's cross-install guarantee (the goal) is unaffected.
- **C2**: `spawn_api_process` strips the `\\?\` prefix before launch, and a
  child with the verbatim arg aborts with EISDIR, so it never becomes a stale
  port-holder.
- **C4**: the fail-open intent is documented in the design doc and in-code; the
  shell has no logging seam at this point. No kill beats a wrong kill.
- **C5**: adding a Windows `cargo test` job is CI scope, not #403; reported to
  the parent as a proposed follow-up that needs a decision before deferring.

## Defender

Confidence 8-9/10: install-scoped identity fixes the regression at its source;
whole-argument boundaries reject `.map`, `--entry=`, and `--entry="..."`;
fail-open is the safer direction; spawn and cleanup share `api_runtime_dir` /
`api_sidecar_entry_path` so they cannot drift. No blockers.
