## codebase-design

- **Deletion test on the new step:** delete it and the repo has no CI execution
  of `backup.encrypted.test.ts`; #402's sentinel is a comment about an env var
  nobody sets, and the skip it guards is indistinguishable from success. The
  step carries behaviour, so it is not shallow.
- **No new seam was invented.** The step is three lines in the job that already
  owns the built artifact. Extracting the repoint into a helper script would add
  an indirection with one caller, and the only dynamic part (which copy resolves)
  is a filesystem fact the runner has to observe anyway.
- **Duplication that does exist:** the built package path
  (`apps/desktop/src-tauri/bin/api-runtime/node_modules/better-sqlite3-sqlcipher`)
  is now written in two places — the proof script's constants and the workflow
  step. Fixing it properly means the job asking the proof script for the path,
  which turns a two-line step into a script invocation whose only job is printing
  a path. Accepted, and fail-closed in the right direction: a wrong path leaves
  the unbuilt pnpm link in place, the binding fails to load, and the sentinel
  turns the run red instead of green.
- **The precedence claim is not taken on trust.** The comment says the local
  `apps/api/node_modules` link wins over `NODE_PATH`; that was probed locally
  before the step was written (see the design doc), so the workaround is aimed
  at a verified mechanism rather than a remembered one.

## improve-codebase-architecture

- **Friction created:** the API test now depends on the desktop build inside one
  job. That coupling is the point (the test must exercise the built fork), and it
  is stated in the step comment rather than left for the next reader to infer.
- **Blast radius of a path change:** if `build-sidecar.mjs` moves the runtime,
  both the proof and the new step go red on the same PR that moves it. Loud, not
  silent.
- **What this lane did not do:** assert the new step's presence in
  `tests/workflow-assets.test.mjs`. That belongs with the already-proposed
  follow-up to pin the required-status contract there, and a YAML substring test
  in this PR would be a shallow test of the file that will change next.
