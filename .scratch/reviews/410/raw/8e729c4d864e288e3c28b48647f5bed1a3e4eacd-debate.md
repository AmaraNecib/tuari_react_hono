## Defender's case

1. **The gate is in the right place, and it is fail-closed.** `prove-encryption` lives in
   `ci.yml:390-436`, path-gated on `encryption` (`:88-95`) which covers `apps/desktop/**`,
   `apps/api/**`, `packages/contracts/**`, `infrastructure/**`, `pnpm-workspace.yaml`,
   `pnpm-lock.yaml`, `package.json`, `ci.yml` — exactly the surfaces that can change the
   native build. The JOB always runs and every step but the skip-echo is gated, so a required
   status check still reports while an unrelated PR pays nothing. Confidence 9.
2. **The proof tests the artifact, not a copy of its logic.** Step 5 boots
   `dist/index.cjs` with `APP_DB_KEY` and lets the real worker take the backup
   (`:436-452`), instead of re-implementing `VACUUM INTO`. That is the correct call for a gate
   whose whole purpose is to stop a *silent* loss of the guarantee. Confidence 9.
3. **`cipher_version` is single-sourced with the build.** The proof calls
   `probeSqlcipherBinding` from `sqlcipher-availability.mjs` (`:295-300`), the same function
   `build-sidecar.mjs:262-271` uses, so the build cannot pass a weaker capability test than
   the gate. Confidence 8.
4. **The plaintext predicate is deliberately *not* shared with the API.** The proof owns
   `SQLITE_HEADER_MAGIC` / `isPlaintextSqliteFile` (`:60, 105`); the API owns its own header
   check. A proof that reused the predicate it is proving could not catch a bug in it.
   Confidence 8.
5. **The obvious false-positive (empty file) is handled.** `isPlaintextSqliteFile` requires
   `header.length === SQLITE_HEADER_MAGIC.length` (`:109`) and `assertEncryptedDatabase`
   rejects a file below the magic size (`:355-360`), so a 0-byte or truncated artifact is a
   red job, not a false green. Tested at `tests/…:36-66` and `:86-97`. Confidence 9.
6. **The backup check is now tighter than the spec demands.** Requiring `snapshot.json`
   (`:150`) mirrors the owner's own definition, and the service's atomic `renameSync`
   (`backup.service.ts:472`) means a marked folder is always complete — so the marker check
   adds strictness without adding flakiness. The equality assertion (`:493`) is
   schema-agnostic and therefore does not drift with a migration. Confidence 8.
7. **All of this is unit-tested on the cheap runner.** `tests/sqlcipher-encryption-proof.test.mjs`
   ran here: 11/11 pass, in ~0.5s, on ubuntu, through an explicit lint step (`ci.yml:41`).
   `check:workflow-assets` and `check:repo-hygiene` also pass (12/12 in the tail); no
   workflow-structure test broke on the new job. Confidence 9.
8. **M2 is a red-CI risk, not a silent-risk.** If the blocked install script is what unpacks
   SQLCipher sources, the failure is a failed job with node-gyp output, in CI, before any
   artifact is published. That is strictly better than the failure mode #410 exists to
   replace. Confidence 7.
