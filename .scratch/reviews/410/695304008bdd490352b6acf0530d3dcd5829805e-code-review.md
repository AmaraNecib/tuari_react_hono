### Item 4 — was dropping the line numbers right, or should they have been corrected?

Dropping was the right call, for three reasons:

1. **The cited lines were wrong, and not trivially fixable.** `lib.rs:2052` at HEAD sits inside `spawn_api_process` (declared `:2049`); the cited `LicenseManager::initialize` handoff is `:2141`. So the number was broken, not merely stale.
2. **A number is only honest if it resolves.** `:2141` is a `match` arm, not the handoff itself; the env-var write the sentence describes is the block at `:2147-2155` (plus the failure arm `:2151-2155`). Re-anchoring would have swapped one over-precise pointer for another, in a doc whose own header disclaims `develop` at a fixed base ("It describes `develop` at this document's base", `:113`) — line numbers there rot by design.
3. **It matches the file's existing convention.** The same file already uses file-only citations at `:197` and `:279`, and round 2 accepted that pattern. Dropping the two outliers makes the file internally consistent. This is not a silent weakening: nothing in the text's enforceability depended on the number, and the sentence still names the symbol (`LicenseManager::initialize`) and the file, which is unambiguous (`grep` finds the handoff at `lib.rs:2141` in one hit).
