## Critical-check verification (reported in full)

1. **Every sync `db.transaction()` writer under the lock — PASS.** Enumerated all `.transaction(` / `raw.transaction(` call sites in `apps/api` (non-test): fifo-lock.ts:235 (the shared util), payment.repository.ts:213 (`deleteIfUnallocated`, already under `connectionLock.run` → `.immediate()`, unchanged and correct), account.repository.ts:191 (Drizzle `db.transaction()` — actually `BEGIN IMMEDIATE` on raw, under the lock), sqlite-bootstrap.port.ts (BEGIN IMMEDIATE under lock), and the six converted sites (company `withTransaction` + 11 `raw.transaction()`, inventory `withTransaction` + `createOutboundTransfer`, invoice-debt `createInvoiceDebt` + `recordInvoicePayment`, invoice `create`/`update`/`delete`, update-history plain write). All route through `runSyncTransaction` → `lock.runSync`.
2. **better-auth session writes — COVERED BY INVARIANT ONLY (documented residual, unchanged from the prior review F6).** `auth.ts` uses `drizzleAdapter(drizzleDb, …)` on the shared connection; the adapter is unwrappable. Protection is invariant (D): no locked transaction spans a real event-loop yield, so a better-auth write can never run while our transaction is open. Verified: the only real yield ever inside a locked tx was the account bcrypt verify; it now runs outside the lock. NOTE (asymmetry, out of scope): better-auth also never takes the FIFO lock, so a better-auth-held transaction (if any) is invisible to `runSync` — our sync writers would not throw busy, and unwrapped plain writers would silently join it. Pre-existing; not part of #322's scope.
3. **fifo-lock refactor behavior-preserving for the async path — PASS.** The `run` rewrite keeps: FIFO tail chaining, `release`-only-resolves tail (no rejection poison), reentrancy throw on same-lock nested `run`, sync-throw → rejection conversion (`Promise.resolve().then(operation)`), release on settle via both handlers, and the `finally`-equivalent (release in `.then`/`.catch`). Added state: `activeCount` (incremented only when a slot actually starts, decremented in both settle paths — no leak on throw/abandon), optional `timeoutMs` (timer cleared on start, `unref()`ed, rejects only while still queued, abandoned slot releases on its turn so the chain stays FIFO). All pre-existing async tests retained and passing (full suite: 64 files / 1088 tests green; tsc and eslint clean).
4. **#339 payment validation intact — PASS.** `git diff origin/develop...HEAD --name-only` contains zero `packages/contracts` or `apps/api/src/modules/payment` files; the only shared-invoice-file edits are the transaction-wrapping + lock-injection hunks (verified hunk-by-hunk — no logic changes). `deleteIfUnallocated` still runs the existence+allocation guard inside one lock-held `transaction.immediate()` critical section; the full payment/invoice suites (200 tests) pass.

## Defender verdict

No blockers. Defenses, with confidence:
- `runSync` primitive (free → run; own-run → join via ALS; foreign-held → `FifoLockBusyError`): **9/10** — the check+execute is atomic w.r.t. the event loop by construction (sync code cannot interleave).
- Async `run` refactor behavior-preserving: **9/10** — FIFO, release-on-settle, sync-throw conversion, and chain-liveness all pinned by the retained pre-existing tests plus the new abandon/FIFO tests.
- Invariant (D) — no locked tx spans a real yield: **9/10** — verified by reading every lock opener: account (bcrypt now outside; in-tx ops are drizzle sync-under-hood), bootstrap (`hasConfiguredUsers` is a resolved-promise microtask hop), recovery-key, payment (`deleteIfUnallocated` tx fully sync; `runInTransaction` callbacks are all sync-under-hood drizzle), invoice (same). No macrotask await remains inside a locked region.
- Timeout bound (secondary acceptance): **8/10** — validated at construction, `unref()`ed, abandons cleanly, queue stays FIFO; the documented caveat (bounds the WAIT, not a hung holder) is honest and matches behavior.
- Sync-site routing + composition-root wiring: **9/10** — single shared lock threaded through every async opener and every wrapped sync adapter (dependencies.ts :140-217).

All three "Done when" clauses are satisfied; one should-fix (D1) deferred to a follow-up, plus documented residuals (D2, D7).

## Residuals documented (not blockers)

- D2 — better-auth session writes protected only by invariant (D); better-auth never participates in the FIFO lock.
- ALS own-run detection remains best-effort (pre-existing, documented in fifo-lock.ts).
