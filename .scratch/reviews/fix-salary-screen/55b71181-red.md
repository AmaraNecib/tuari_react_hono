## Failing behaviours (red) and why

| Test | Failure at base |
| --- | --- |
| `defaults the amount to the known wage when the wage period is unknown` | `expected '' to be '30000'` — the proposal was gated on `salaryPeriod !== null`, so a known wage with a null period left the amount empty. |
| `shows every payment and no next page when the history is exactly one page` | `Unable to find an element with the text: 1-10 من 10` — no pagination controls existed. |
| `windows the payment history through the shared pagination controls` | no `التالي` button — every row rendered. |
| `clamps the payment page on the first render after the history shrinks across a boundary` | no `التالي` button. |
| `resets the payment page to 1 when the search changes` | no search input. |
| `filters the payment history by project and resets to page 1` | no project filter. |
| `filters the workers by period and resets to page 1` | no period filter. |
| `shows a no-results message instead of dead controls when a filter matches nothing` | `Unable to find a label with the text of: بحث باسم العامل...` — no search field. |

Item 5's already-satisfied behaviours (the #420 full-salary default and
editability) were green at base; only the null-period case was red, and it is
the one this lane changed.
