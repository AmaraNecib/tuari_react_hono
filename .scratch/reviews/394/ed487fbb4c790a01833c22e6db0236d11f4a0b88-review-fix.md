# Review-round fix — seat check must not load every employee (#394 / PR #401)

**Issue:** #394 — license seat limit on active employees
**Tier:** High-assurance (licensing)
**Base:** `develop`
**Code commit (HEAD):** `ed487fbb4c790a01833c22e6db0236d11f4a0b88`
**Date:** 2026-09-26

## Finding addressed

**P2** `apps/api/src/modules/company/employee-seat-limit.ts:61` — "Seat checks
load every employee": on an active license, every employee
creation/reactivation listed and sorted all employees just to count the ACTIVE
ones.

## Fix

- Added `countEmployees(filters?: EmployeeListFilters): number` to
  `WorkforceRepository`.
- SQLite adapter (`sqlite-company.repository.ts`) runs a single
  `SELECT COUNT(*)` over the shared employee filter conditions. The condition
  builder was extracted to `buildEmployeeFilterConditions`, now reused by
  `listEmployees`, `listEmployeesPaged`, and `countEmployees` so status/search
  semantics cannot drift.
- In-memory adapter reuses one `filterEmployees` predicate for `listEmployees`
  and `countEmployees`; the `SqliteWorkforceRepository` /
  `InMemoryCompanyRepository` delegating wrappers forward the new method.
- `assertActiveEmployeeSeatAvailable` now calls
  `repository.countEmployees({ status: "ACTIVE" })`; the narrow seam is
  `Pick<WorkforceRepository, "countEmployees">`.

Behaviour is unchanged: `maxUsers > 0` caps only ACTIVE employees under an
`active` license; `trial`/`grace`/unset/`0` stay uncapped; the refusal message
keeps the limit and the current count.

## Tests

- The 18 pre-existing behaviour cases pass unchanged. The direct-helper fake now
  fails loudly if `listEmployees` is called, so those cases also prove rows are
  never materialised.
- New: helper call-shape test asserts `countEmployees({ status: "ACTIVE" })`.
- New: adapter test pins count/list filter equivalence (no filter, status,
  search, roleId, LIKE wildcard).
