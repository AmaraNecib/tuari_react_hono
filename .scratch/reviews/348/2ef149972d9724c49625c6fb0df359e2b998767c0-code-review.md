## Spec

1. **Enumeration is complete.** The design names and the implementation
   contains all **38** writer methods: **24 company** (17 public + 7 private
   history/reassignment helpers), **12 inventory**, and **2 invoice**.
   `git`/TypeScript structural audits found every database `.run()` in the
   three target adapters inside an enclosing `runSyncTransaction`. The
   pre-existing multi-statement methods use one enclosing wrapper around their
   complete statement sequence; a separate wrapper around every individual
   statement is not required.
2. **Tripwire semantics are preserved.** `runSyncTransaction` still executes
   immediately when free or in the lock's own `run` context, throws
   `FifoLockBusyError` for a foreign active flow, and permits nested
   better-sqlite3 savepoint joining. The integration suite exercises a real
   await before an own-run writer (`transaction-lock-guard.test.ts:588-598`),
   while `fifo-lock.test.ts` and the company repository tests cover primitive
   busy, rollback, external-transaction savepoint, and queue behavior.
3. **Tests match the acceptance.** The new integration suite covers
   representative company, inventory, and invoice writers for busy rejection,
   post-release durable success, async rejection propagation, the upsert
   no-trace path, and the own-run join path. Structural coverage compensates
   for the representative rather than one-test-per-method shape.
