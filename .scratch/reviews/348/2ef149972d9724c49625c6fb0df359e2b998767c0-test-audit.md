## Process

Three read-only test-audit agents reviewed the committed diff, the changed
integration suite, the FIFO primitive tests, the three adapters, the design,
and the existing company/invoice workflow tests:

- **Edge Case Hunter:** races, foreign-held behavior, no-trace/rollback,
  savepoints, no-ops, and financial-ledger failure paths.
- **Coverage Analyst:** acceptance criteria, direct versus structural coverage,
  writer enumeration, join/nesting behavior, and duplicate coverage.
- **Quality Reviewer:** names, async assertion forms, release safety, setup
  isolation, determinism, and readability.

## Verdict

No implementation blocker was found for the stated acceptance. The production
change structurally covers **38/38 enumerated writer methods**:

- **24 company** — 17 public writers plus 7 private history/reassignment
  helpers;
- **12 inventory**;
- **2 invoice**.

A TypeScript AST audit independently found every database `.run()` in the three
target adapters inside an enclosing `runSyncTransaction`. The direct integration
suite is representative rather than one-test-per-method, and the structural
audit is the completeness sentinel.

## Coverage confirmed

- Foreign-flow tripwire behavior and durable retry for representative company,
  inventory, and invoice writers.
- Synchronous `toThrow(FifoLockBusyError)` and asynchronous
  `rejects.toThrow(FifoLockBusyError)` forms are used correctly.
- `expectBusyWhileHeld` and `expectRejectsBusyWhileHeld` release and await the
  holder in `finally`, preventing a failed assertion from leaking the lock.
- `upsertEmployee` verifies both the employee and its nested CREATED
  `employee_state_history` row; the busy attempt is asserted to leave no row or
  history trace (`transaction-lock-guard.test.ts:344-397`).
- Own-run joining across a real await is covered with `createRole` inside
  `lock.run` (`transaction-lock-guard.test.ts:588-598`).
- FIFO, foreign busy errors, queue recovery, precedence inversion, timeouts,
  and primitive-level await-hop propagation are covered by
  `apps/api/src/infrastructure/database/fifo-lock.test.ts`.
- Existing repository tests cover nested savepoint rollback and an externally
  opened raw transaction (`apps/api/src/modules/company/sqlite-company.repository.test.ts:375-444`).
- Existing invoice module tests cover rollback after a coordinated debt/payment
  failure (`apps/api/src/modules/invoice/invoice.module.test.ts:856-913`).
