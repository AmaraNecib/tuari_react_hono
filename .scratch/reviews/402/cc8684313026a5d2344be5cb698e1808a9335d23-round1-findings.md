## Findings addressed

### 1. P1 - a stale addon passed the gate (`sqlcipher-availability.mjs`)

**Finding.** The predicate only checked that a file existed, so an addon built
against a different Node ABI was accepted; the sidecar bundled the current Node
with an incompatible binary and the failure surfaced at runtime.

**Fix.** New `probeSqlcipherBinding({ nodeExecPath, runtimeDir, execFile? })`.
After the runtime is copied, `build-sidecar.mjs` runs the copied fork with the
**copied** Node executable (`node -e`, cwd = sidecar root), sets a key and
`cipher_compatibility = 4`, and requires a non-empty `PRAGMA cipher_version`,
the same capability probe the API applies at runtime. It throws with the
loader's own stderr when the addon cannot load. `execFile` is injected so the
wrapper (success, loader stderr, empty version) is unit-tested, and one test
spawns a real synthetic addon that exists but cannot load. No ABI version
marker file is written; the load test is authoritative.

### 2. P2 - `typecheck` left a plaintext runtime, and packaging did not re-validate

**Finding.** `typecheck` built `--allow-plaintext` into `src-tauri/bin`; a later
direct `tauri build` could package it without re-running the strict gate.

**Fix (two changes, both wanted).**

- `typecheck` now passes `--ephemeral`: the build runs in a `mkdtemp` directory
  under the OS temp root and the directory is removed in a `finally`, including
  when the gate refuses. Nothing plaintext is ever written to `src-tauri/bin`.
  Chosen over "remove afterwards" because it never touches the packaged
  directory at all; `cargo check` only needs the tracked `bin/api-runtime` and
  `bin/node.exe` placeholders for tauri-build's resource copy, so typecheck
  still passes.
- `tauri.conf.json` `beforeBuildCommand` now runs the frontend build **and** the
  strict `sidecar:build`, so `tauri build` always re-validates and can never
  package a runtime the strict gate would reject. `build` / `tauri:build` were
  reduced to `tauri build` so the sidecar build runs once.
- `--allow-plaintext` remains only on the typecheck path.

### 3. P2 - the installer smoke check could pass on plain `better-sqlite3`

**Finding.** `scripts/smoke/installer-smoke.mjs` searched a candidate list that
included plain `better-sqlite3` at `build/Release` and the fork at
`build/Release` (plain's layout). Plain is now always copied, so the check could
pass on an artifact with no encryption support.

**Fix.** The check is now three parts: plain binding at `build/Release`, the
fork independently at its real loader path `build/better_sqlite3.node`, and a
real capability probe (`cipher_version`) run with the extracted `bin/node.exe`.
`docs/release-verification.md` was updated to describe the new check set.

### Additional local-Greptile P2s (also fixed)

- **Successful path untested.** Added a positive control that spawns the real
  probe against a synthetic loadable package that reports a cipher version. A
  real Windows-native SQLCipher build still needs the Windows SDK (see bounds).
- **Smoke result overstated.** The docs briefly claimed a 24/24 run; the two new
  SQLCipher checks have not run against a full artifact. Reverted to the
  historically verified 22/22 and marked the SQLCipher checks pending.
