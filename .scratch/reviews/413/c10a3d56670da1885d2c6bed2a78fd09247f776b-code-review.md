## Why one bound, and which one

The contract bound wins. `MAX_MONEY_DZD` is `Number.MAX_SAFE_INTEGER`, a
precision limit rather than a business ceiling, so the only prices it rejects
are values whose arithmetic is already undefined. The invoice path has no
evidence for a higher ceiling, so the fix aligns the input instead of widening
the charge default. `inventoryAssetUnitSchema` is also bounded: it is the shape
the invoice path writes and every response embeds, so leaving it open next to a
bounded charge contract would keep the two-ceiling bug alive.

## Standards axis

- One money rule: the invoice input, the stored entity shape, the charge default
  and the charge amount all parse `nonNegativePaymentAmountSchema`, which shares
  `MAX_MONEY_DZD` with `paymentAmountSchema`.
- The module seam repeats the wire gate's schema rather than a hand-rolled
  comparison. That is the established #289 pattern in `payment.ts`, so a direct
  caller cannot store money the RPC input rejects.
- The aggregate guard lives in `AssetChargeService` next to the total it
  guards; `InventoryService` still only composes the charge service.
- The typed error uses the existing `InventoryError("BUSINESS_RULE", message,
  fieldErrors)` shape, so the RPC layer maps it without a new error path.
- `roundMoney` still normalizes float noise at the money boundary; the guard
  runs before it because the running total is monotonic and non-negative.

## Residual and accepted

- Bounding `inventoryAssetUnitSchema` means a legacy row above
  `MAX_SAFE_INTEGER` would fail to serialize. Accepted: the invoice input now
  rejects such a price, the value is unusable as money anyway, and an unbounded
  read shape beside a bounded write shape is the bug being fixed. The design doc
  records the trade-off.
- The round-1 test that feeds `resolveDefault` a stored price above the bound
  (`Number.MAX_SAFE_INTEGER + 1`) stays. It now pins defense-in-depth against
  corrupt stored data, not a legal input path.
- No debate evidence exists for this issue in any round. Reported to the parent
  as a gate gap; not silently waived.
