## Critic findings and synthesis

| # | Sev | Finding | Decision |
| --- | --- | --- | --- |
| C1 | 4 | The write-time gate called `listChargesByProject`, so a bulk invoice re-scanned the whole project and resolved its name once per asset. | **Fixed** — added `sumLiveChargesByProject(projectId, excludeChargeId?)` to the port (one aggregate query in sqlite, one reduce in the double); the gate uses it. |
| C2 | 3 | The correction error's "current total" excluded the corrected charge, so it could not be reconciled with the project view; and the write gate and read backstop had two different texts for one condition. | **Fixed** — the helper now reports the full LIVE total and subtracts the replaced amount only for the overflow test; one `projectTotalOutOfRange(currentTotal, field)` builder serves both paths, naming the limit and the current total. |
| C3 | 3 | The failed-default fix keyed only on `isError`, so a pending query still rendered `سعر الشراء: 0` (percent disabled, no warning) — the same defect in another query state. | **Fixed** — a pending query renders a `chargePriceLoading` hint; only a settled price renders the price hint. |
| C4 | 2 | With the price unavailable, a blank amount still submitted `null`, re-running the server default read that just failed. | **Fixed** — submit is blocked (`chargeRequired`) until an explicit amount is entered. |
| C5 | 2 | Voiding an already-voided charge reported the correction wording `لا يمكن تعديل احتساب ملغى`. | **Fixed** — `requireLiveCharge(chargeId, action)` reports the action-specific message. |
| C6 | 2 | `resolveDefault` runs before the write transaction. | **Accepted** — safe on the single synchronous better-sqlite3 connection; only the aggregate check needs the lock. Documented in the design doc. |
| C7 | 3 | The N+1 fix covered only the project path; the critic claimed `getAsset` runs `listByUnit` once per asset on the location-contents screen. | **Dismissed (partly factual)** — `getAsset` is a single-unit detail read; the location-contents screen does not call it per asset. `listByUnit` still resolves a name per charge, which is correct because a unit's chain can span projects, and that path is out of this finding's scope. |
| C8 | 1 | The real-sqlite `describe`'s `afterEach` closed `db` unconditionally, so a future test without `createRealHarness()` would TypeError. | **Fixed** — `db` is optional and `db?.close()`. |

Defender notes accepted and documented:
- An already-over-bound legacy project cannot be corrected downward when the
  other LIVE charges alone exceed the bound; **voiding is the escape hatch**
  (`voidCharge` deliberately skips the aggregate gate). Recorded in the design
  doc.
- The cross-process TOCTOU claim is defended by the `AND status='LIVE'` UPDATE
  by construction; there is no separate-process test (a real interleave is
  impossible on one synchronous connection, so the sequential stale-write test
  is the faithful available proof).
