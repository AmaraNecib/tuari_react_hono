## Critic

**C1 (🟠, fixed). Prefill still used a stale value when the refetch FAILED.**
Gating only on `isFetching` leaves the TanStack-v5 "error with retained data"
state: `data` holds the previous open's amount and `isFetching` is false, so the
effect prefills it. Fixed by also returning on `isError`; a new test pins it.
The blank field is safe because `null` makes the server resolve the default at
write time.

**C2 (🟡, accepted). The batch running total rounds per step.** The read rounds
once over the whole list. With all charged amounts now 2-decimal the two agree
mathematically, but a legacy sub-cent row could theoretically put them a cent
apart exactly at the bound. The batch path is only reached from
`createInvoiceGroup`, where every amount comes from `resolveDefault` (rounded),
so the divergence is unreachable today. The single-placement path keeps the
exact projected-list check.

**C3 (🟡, accepted). Finding 3 does not add the history to the location section
itself.** The section is location-scoped by construction, so a unit with no
location cannot appear there. The fix adds the per-unit view the brief offered
as the alternative (the invoice's asset list). A future "unassigned units" list
would be a separate feature.

**C4 (🟡, accepted). Finding 6 replaced the inline consumable transfer form.**
The page no longer fetches warehouses/projects, but the consumable transfer is
now two clicks (button -> dialog) instead of inline. This is the only way to
make "enable them when the dialog opens" literally true while keeping the
consumable transfer functional; it also unifies the transfer entry point.
Behaviour (quantity, destination, source) is preserved; the server still
validates availability.

**C5 (💡, not a defect). `createPlacementCharges` resolves defaults before
`createCharge` per placement but after the single project read.** Sequential
defaults are preserved because the read is only the aggregate gate, not the
default source; `getLastChargeAmount` is still called as the batch writes.
