## Defender points accepted and documented

- The gate projection is exact, not approximate: placement prepends the new
  row (max rowid ⇒ read index 0) and correction replaces in place (UPDATE keeps
  the rowid) — so the gate computes the identical post-write array the read
  computes.
- `queryAuth`'s `requireWorkspaceAdmin` stays outside the new `try`, and
  `toFailureResult` rethrows non-`InventoryError`, so no auth or unexpected
  error is silently turned into a failure envelope.
- `listByUnit` staying unmapped is contract-correct: its `createListSchema`
  output has no failure branch, so mapping there would fail output validation.
- `inArray` over charge ids has a ~999-variable bound; unreachable for a
  per-unit placement chain, but noted.
