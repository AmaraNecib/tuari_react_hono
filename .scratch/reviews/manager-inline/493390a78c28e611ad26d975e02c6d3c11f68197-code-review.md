## Standards

One shared implementation is real: `useEmployeeInlineCreate` owns the mutation,
row shape and failure contract; `useEmployeeInlineCreateSelection` adds the
selection bookkeeping; `project-manager-inline.ts` / `warehouse-manager-inline.ts`
carry only role id + labels. i18n keys are wired in `ar.ts` (only locale) and
pass the repo i18n-key check. The hook's failure contract is now: server
`AppMutationError` message (first field error preferred) passes through; every
other failure is wrapped in the localized `errorMessage`; a missing id fails
loud instead of fabricating.

## Spec

The owner asked for inline create on the project form. `c2631064` delivered it;
`fa3f3784` extended the shared pattern to the warehouse form (replacing a copy
that always failed at the wire gate with `roleId: ""`) and removed the debt
internal-worker create.

| Spec question | Verdict |
| --- | --- |
| Extending to warehouse correct? | **Yes.** The old warehouse copy always failed (`roleId: ""` fails `entityIdSchema`); replacing it with the working hook is a fix, not scope creep. |
| Removing the debt worker create the right call? | **Yes.** `workforce.service.ts` rejects an ACTIVE `worker` without a direct manager and a project; the text-only dialog cannot collect either. The external-counterparty create is untouched. A third option (create the worker non-ACTIVE) was considered and rejected: a debt party must be selectable, and inventing a half-formed worker is worse than routing creation to the employees form. |
| Missing/partial requirement | None material; the clear-manager regression was the only functional gap and is fixed. |
