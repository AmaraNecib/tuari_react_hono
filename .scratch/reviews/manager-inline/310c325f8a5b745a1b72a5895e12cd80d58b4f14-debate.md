## Defender points that held

- One shared implementation: the mutation, row shape and failure contract live once in `use-employee-inline-create.ts`; callers carry only role id + labels.
- Real role ids per caller, derived from `derived.roles` by key in `home-view-page-content-detail-pages.tsx`; the created person lands in the right manager dropdown because `buildManagerOptions`/`buildWarehouseManagerOptions` filter on the same role key.
- Real returned id from `success.item.employees`; the previous `{ id: "new" }` / `{ id: "" }` fabrications are gone.
- Relation invariants hold: `managerId: null` and no `projectId`; `createEmployeesBatch` only requires/forbids those for `worker` rows.
- Removing the debt worker create is correct: the dialog is text-only and the API requires an ACTIVE worker to have both a direct manager and a project.
