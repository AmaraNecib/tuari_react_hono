## Defender highlights (confirmed)

- Port boundary clean: service imports only `node:crypto`, `company-time`,
  `recovery-key.types`; all Drizzle/SQLite confined to the adapter.
- `toRecord()` centralizes the one unsafe status cast at the persistence
  boundary; the service's own cast disappeared (service is now fully typed).
- Crypto (generation + SHA-256) stays in the service; the adapter never sees
  plaintext — a compromised adapter leaks zero key material.
- Handler `async`/`await` conversion was not cosmetic: sync callbacks would
  have JSON-serialized the returned Promise as `{}`.
- Tests updated mechanically (awaits + `mockResolvedValue`), assertions
  untouched; 601 pre-existing tests pass with zero assertion drift.

## Residual risks

- `withTransaction`'s mutex serializes only flows that go through the port's
  `withTransaction` (currently only `generateKeys`); other port calls
  (`insertKey`, `updateKeyStatus`) are single statements and inherently atomic.
- If future code opens transactions on the shared connection outside the port
  (e.g. bootstrap flows), `withTransaction` joins them (`inTransaction` guard)
  rather than failing — acceptable for the single-admin desktop app; documented
  in the adapter header.
