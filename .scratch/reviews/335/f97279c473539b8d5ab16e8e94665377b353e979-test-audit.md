## Edge case hunter findings

| # | Risk | Finding | Location |

| E1 | 🟠 subtle | **Rebuild-failure atomicity untested.** No test injects a mid-rebuild failure (e.g. CHECK violation on copy) to prove: legacy table intact, no key recorded, `foreign_keys` restored to ON. | E2 | 🟠 landmine | **`alreadyRestrict` whole-table substring scan.** `tableSql.includes("ON DELETE RESTRICT")` skips the rebuild if the phrase appears anywhere; today invoice_id is CASCADE so correct, but no test pins the realistic legacy shape (the test fixture omits the invoice_id FK entirely). | `schema.ts:1411`, `schema-migrations.test.ts:532-541` (fixture) |
| E3 | 🟠 subtle | **Guarded-delete race now surfaces a raw FK error.** Under old CASCADE the theoretical post-COUNT/pre-DELETE window silently cascade-deleted; under RESTRICT the same window throws `FOREIGN KEY constraint failed` out of `transaction.immediate()`, bypassing the module's NOT_FOUND/HAS_ALLOCATIONS error mapping → raw 500. Lock + BEGIN IMMEDIATE close the in-process window by construction; no test pins that the guarded delete can never throw. | `payment.repository.ts:195-228` |
| E4 | 🟡 | **Missing-table path** (`tableSql=""` → rebuild → `ALTER TABLE` throws, bricks startup). Unreachable while `schemaStatements` runs first; untested. | `schema.ts:1410` |
| E5 | 🟡 | **State-key trust gap:** if the key exists while the live table is still CASCADE, migration silently skips; no re-validation of actual FK. | `schema.ts:1397-1403` |
| E6 | 🟡 | **Fixture drift:** legacy fixture drops real `invoice_id` FK and `CHECK(amount>0)`; data preservation tested with exactly 1 row; 0-row copy untested. | `schema-migrations.test.ts:532-541` |
| E7 | 🟡 | **Drizzle declaration drift (pre-existing):** `schema/payment.ts` declares `amount_dzd` and no invoice_id FK vs DB's `amount` + FK. File touched by this PR; no runtime impact (raw SQL). | `schema/payment.ts` |
